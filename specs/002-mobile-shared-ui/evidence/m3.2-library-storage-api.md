## 3. Implemented behavior

- **Identity**: writes accept canonical qualified ids only (`tmdb:movie:N`, `tmdb:tv:N`, `anilist:N`, `jikan:N`, `imdb:ttN`). The unqualified legacy alias `tmdb:N` is rejected with 400 `invalid_request` — it is a read-only catalog alias and can never establish a library key. `tmdb:movie:123` and `tmdb:tv:123` are independent memberships (proven by test).
- **Writes** (`internal/library` `Store.Write`): resolve-before-lock (one bounded metadata call at most; the serialization lock is never held across a provider call), transactionally serialized through the household revision row, get-or-create under `FOR UPDATE` + unique constraint, update ONLY the requested flag, set/clear only that collection's timestamp. No-op/retry writes return committed state with an unchanged revision and no reorder. A both-false row is retained but appears in no collection.
- **Metadata snapshots**: first membership requires resolvable metadata (else 404 `title_not_found`; resolver degradation → 503 `providers_unavailable`). Existing memberships whose metadata disappeared keep the stored snapshot, are labelled `metadataAvailable:false`, and stay readable/removable. Reads never call the resolver — snapshot columns only (N+1-free; proven by call-counting test).
- **Reads** (`Store.Page` / `Store.Overview`): repeatable-read snapshots — revision, full-scope totals, previews and page items are mutually consistent even when a write commits between the count and page reads (proven with an in-transaction write hook). Overview = one batched read with movie/series/anime shelves always present, bounded previews (6), zero-count shelves included.
- **Cursors**: opaque base64-JSON tokens embedding collection+kind+sort+last tuple (keyset pagination; mixed-direction recent order handled explicitly). Scope mismatch in any dimension → 400 `invalid_request`; garbage tokens → 400. Sort switch resets the cursor.
- **Revisions**: monotonic int64 advanced transactionally per effective change; wire format is the lossless decimal string (`RevisionString`). Proven beyond JavaScript's safe integer range (seeded 2^53+ value; exact string preserved).
- **HTTP** (`internal/httpapi/library_handlers.go`): `GET /v2/library`, `GET /v2/library/overview`, `PUT /v2/library/{id}/watch-later|favourite` exactly per contract (envelope, both flags + post-commit revision in write responses, `sourceRev` mirrors the snapshot revision until M4 introduces its own source revision). Errors reuse the versioned envelope (`invalid_request`, `title_not_found`, `providers_unavailable`). Origin-allowlisted CORS and OPTIONS preflights match the catalog surface. `Register` is a no-op without a storage-backed service — routes absent, like an older server.
- **Capability**: `library.household.v1` is appended to `/v1/version` capabilities in the composition root ONLY when `library.NewStore` verifies the initialized schema; otherwise it is logged as unavailable and not advertised (main.go; proven by `TestNewStoreRequiresInitializedSchema` + live old-binary runs).

Server-side alias support is additive; rollback does not drop household data.

## 6. Concurrency results

- 8-way opposing writes to one field: exactly one row; highest returned revision == committed household revision; committed row flag == last effective writer's response; collection total consistent with the final flag (inactive when the last commit was `false`).
- 2-way parallel writes to different fields: both flags committed, revisions exactly one apart (serialized through the household row).
- Read snapshot: a write committed between count and page read is invisible to that page (revision/total/items coherent) and visible to the next read.

## 8. Rollback strategy

- Binary rollback: old binaries ignore the new tables and keep serving (proven live); memberships are retained additively and a new binary resumes them.
- Migration rollback: 007 is additive; reverting the binary alone is sufficient. There is no automatic down-migration (consistent with the existing migration set); dropping the two library tables would be a manual, explicit operation.
- Code revert: M3.2 changes are isolated to `migrations/007*`, `internal/library/`, `internal/httpapi/library_handlers*`, and `cmd/vod` wiring; reverting them leaves M3.1.1 and all earlier behavior intact.
