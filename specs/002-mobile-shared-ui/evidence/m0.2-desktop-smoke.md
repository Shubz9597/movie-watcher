## Repairs during this session (found by the failing 18-check suite and by review)

1. **`library-sync.ts` jitter drop** (root cause of the 17/18 failure): a tick landing a few ms before the 15s window opened was dropped and waited a full second interval (~30s effective), breaking the ≤20s cross-client removal contract. Now schedules a short catch-up for the remaining milliseconds. Regression test added (`library-sync.test.mjs`).
2. **`library-store.ts` lost refresh**: an overlapping `refreshAll()` was silently discarded, so a poll colliding with an in-flight refresh was lost for a full interval. Overlapping calls now queue exactly one follow-up pass. Regression test added.
3. **`serve-browser.mjs` traversal boundary**: `startsWith(distDirectory)` accepted sibling directories (e.g. `dist-browser-evil`); now requires the `path.sep` boundary. Missing extension-bearing assets now return truthful 404s instead of the SPA shell with 200. Regression tests added (`serve-browser.test.mjs`).
4. **`staging.ps1` double-start guard**: only the backend PID was checked; a live frontend/stub beside a dead backend allowed a masked double-start. All recorded PIDs are now checked.
5. **`verify-staging.mjs` tautology**: "production frontend loads" asserted `titleA.length >= 0` (always true); now asserts both React roots actually mounted children.
6. **`server_config.go` stale claim**: the comment "no write endpoint is reachable through it" (opaque `null` origin) became false when M3.2 put library PUT writes behind the same allowlist. The packaged file:// desktop renderer legitimately writes the Library from `Origin: null`, so the opaque-origin write boundary cannot be closed without breaking the desktop app; the comment now documents this honestly and points at the M5 hardening path (serve the renderer from a non-opaque origin, then drop "null" from writes). Recorded in HANDOFF §11 as a known accepted boundary.
7. **Stale Windows MPV binding**: all ignored local `.node` artifacts exported only `MpvHandle`, although the checked-in Rust source also defines the child-window API. The canonical `index.win32-x64-msvc.node` was rebuilt locally with `cargo build --release`; the wrapper now exposes all five required functions. The production loader now rejects incomplete candidates, the smoke fails early with a rebuild instruction, and `player-state-contracts.test.mjs` covers the required surface. The rebuilt binary is intentionally gitignored, so each fresh Windows build environment must build it from source before packaging.
