# M1.4 native mobile foundation evidence

Date: 2026-09-12. Host: Windows workstation.

This evidence distinguishes implemented code, deterministic tests, native compilation, and physical-device verification. It does not claim an iOS build, an Android APK build, or device playback.

## Implemented

### Staging and playback service integration

- `staging.ps1 Make-PlaybackFixtures` generates deterministic direct, remux, transcode, SRT, WebVTT, and ASS fixtures beneath the ignored staging data directory.
- Playback capability remains gated by working `FFMPEG_PATH` and `FFPROBE_PATH` values.
- This host has no configured FFmpeg installation, so host playback verification truthfully skips. The M1.3 container evidence remains the deterministic FFmpeg proof.

### Capacitor shell

- Capacitor core, CLI, Android, and iOS dependencies are pinned to 8.5.2.
- The mobile build uses the shared React application and exactly one React root.
- Settings is an overlay controlled by `SettingsOverlayController`; it does not compete with the shared hash router.
- Composition-owned Library and native-player resources are disposed when the mobile shell unmounts.
- Generated build products and machine-local native configuration remain ignored; native project source is retained.

### Shared playback client and controller

- The session client probes `playback.compat.v1`, accepts only a 40-character hexadecimal torrent identifier, maps server failures to typed errors, and resolves only contract-relative or exact same-origin playback URLs.
- The native controller creates and deletes playback sessions, forwards only opaque playback URLs, writes bounded progress updates, restores confirmed resume positions after media attachment, and emits terminal events exactly once.
- Every native operation and event is tagged with a web-selected `playId`.
- Dismiss and seek operations are playId-scoped in JavaScript, Swift, and Kotlin. A late completion from a superseded start cannot clear, seek, or dismiss its replacement.
- Native listener registration completes before playback begins. Listener handles are retained and removed during disposal.
- A failed server-origin persistence check restores the previous runtime origin.

### iOS adapter

- The Swift plugin uses `AVPlayerViewController` for direct Range and HLS playback, produces time and terminal events, handles audio interruptions, and removes observers during teardown.
- Dismiss, seek, and delayed dismissal callbacks verify `playId` ownership before changing the current player.
- AVFoundation errors are replaced with bounded generic text before crossing the bridge.
- HLS WebVTT renditions are supported by AVPlayer. Standalone direct-play sidecar WebVTT is not yet attached and remains an open device task.
- The plugin is registered in `MainViewController` and present in the Xcode project.
- Status: source implemented and statically reviewed; not compiled because macOS/Xcode is unavailable.

### Android adapter

- The Kotlin plugin launches a Media3 playback activity for direct and HLS session URLs.
- Media3 sidecar WebVTT configuration, time events, terminal events, Back dismissal, audio focus, and player cleanup are implemented.
- Static current-player state is replacement-safe, and seek/dismiss operations require the matching `playId`.
- Cleartext remains refused by default, with only documented development origins allowed.
- Status: Gradle scripts parse; `assembleDebug` has not run because the Android SDK is unavailable.

### Origin and security boundaries

- Settings probes `/readyz` and `/v1/version` before saving an origin.
- Unreachable and incompatible servers are not persisted.
- Origins are restricted to normalized HTTP(S) origins without credentials, paths, queries, or fragments.
- Capacitor CORS origins are pinned to `capacitor://localhost` and `https://localhost`; wildcard, null, unrelated, and lookalike origins remain rejected.
- Magnets, provider credentials, and server secrets do not cross the native bridge.

### Subtitles and remaining scope

- Session-owned WebVTT tracks reach both native adapters: HLS renditions on iOS and HLS/sidecar WebVTT on Android.
- Fixture resolution discovers SRT, VTT, and ASS sidecars with non-sensitive labels.
- External OpenSubtitles results from `/v1/subtitles` are not wired into the native session client yet.
- Direct-play iOS sidecar WebVTT and external subtitle selection remain open; therefore M1.3.7 and M1.4.7 remain unchecked.
