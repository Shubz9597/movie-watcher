# M4.2 evidence — shared Home recommendations UI

Executed: 2026-09-10 (branch `001-build-torwatch-version` @ `5e9c648` + preserved M3.1.1–M3.4 diffs). Scope: M4.2 ONLY — the shared recommendation row and See-all view over the M4.1 endpoint. **No native packaging, playback, M5/M6 work.**

## 1. Implemented behavior

- **`src/components/shared/RecommendationRow.tsx`**: one shared implementation rendered by desktop (Electron) AND the phone/browser entry from the same source:
  - `RecommendationRow` on Home (after the trending rails; self-contained — a missing capability renders NOTHING, a failure renders a bounded Retry row that never blocks or replaces the rest of Home);
  - `RecommendationsAllPage` (See-all route `recommendations`, lazy-loaded in both entries) with the full bounded list (server max 20), degraded note, and a truthful empty state;
  - both are hook+pure-view splits (`RecommendationRowView` / `RecommendationsAllPageView`) so tests and captures render exact states deterministically.
- **Truthful states**: loading skeleton (reserved geometry), favourite-based results with the server's verbatim reason ("Because you favourited X") under every card, `fallback` cold start rendered as the labelled "Popular picks" section (never a favourite claim), `degraded` announced in text, failure → bounded friendly copy + labelled Retry, empty → "No recommendations right now…" (See-all) / section absent (Home row). An older server (capability absent) renders no section at all.
- **Stale/cross-origin safety**: every request captures the shared origin generation at start; a response that raced a switch is discarded (`assertFreshResponse`). Origin-scoped state is component-local and refetched after a switch — no cross-origin data application.
- **Qualified opaque ids**: navigation uses `lib/canonical-route.ts` (`titleRouteParams`) — shared with the Library — carrying kind + numeric id plus the provider/mediaKind namespace for TMDb anime; canonical ids are never stripped or rebuilt as `tmdb:N`.
- **Exclusions** are server-owned (M4.1); the client renders the server list verbatim with no local filtering or re-ranking.
- Accessibility: cards are real buttons with titled accessible names ("Title, Because you favourited X" / ", popular pick"), See-all/Retry have specific labels, focus rings from the shared token, 48px control targets; motion inherits the shared route-enter tokens (reduced-motion collapses via CSS).
- **Dev-only capture route** (`recommendations-states`, fixture entry only) mounts the real components with the deterministic contract fixture fetch (`?recs=<scenario>`, `platform/recommendation-fixtures.ts`); no production path imports fixtures.
