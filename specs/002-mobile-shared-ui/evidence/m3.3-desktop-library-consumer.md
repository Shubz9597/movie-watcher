# M3.3 evidence — first desktop Library consumer (server-backed)

Executed: 2026-09-09 (destination PC, branch `001-build-torwatch-version` @ `5e9c648` + the uncommitted, preserved M3.1.1 and M3.2 diffs). Scope: M3.3 ONLY — one desktop (Electron) server-backed Library consumer over the M3.2 API. **No M3.4 phone/browser enablement, no polling/reconnect sync, no recommendations (M4).**

## 1. Implemented behavior

- **Server-backed store** (`src/lib/library-store.ts`): `LibraryStore` is the framework-free state owner implementing `LibraryController`:
  - availability gated on `/v1/version` advertising `library.household.v1` — `available` / `unavailable` (reachable server without the capability, incl. older servers) / `unreachable` (a null version response is disambiguated by one probe) / `checking`. NO localStorage, device-local membership, or direct-provider fallback exists anywhere on the path (structurally asserted by a test running without any localStorage).
  - revisions are lossless decimal strings compared **per title/resource** with BigInt (`isNewerRevision`); no `Number()` conversion; one resource's revision never suppresses another's response.
  - writes serialize per title/field (promise-chain queue); rapid/repeated clicks enqueue with targets computed from the latest intent; no offline queue.
  - pending → success reconciles from the COMPLETE server response (BOTH flags + revision); failure restores the confirmed server state, keeps the last intended target, and exposes `retry()` (Retry re-issues exactly that target).
  - stale/superseded reads (request-sequence guard per cache key) and cross-origin late responses (generation guard) are discarded, never applied.
  - an origin switch clears ALL origin-scoped state (caches, memberships, queues) and re-checks the capability on the new origin (subscription to the shared origin service).
  - post-mutation invalidation: the affected collection's overview/page caches are dropped so the next ensure refetches fresh server state; the title's membership is reconciled from the write response.
- **Shared accessible icon toggle** (`src/components/shared/LibraryToggle.tsx`): one `LibraryToggle` per field (bookmark = Watch Later, heart = Favourite); bare icon, shared 48px target + focus ring, `aria-pressed`, `aria-busy` while pending, screen-reader live region announcing pending/success/failure in text; error state shows a visible red ring, the confirmed state restored, and "activate to retry" as the Retry affordance. Independent flags: one toggle never overwrites the other.
- **Desktop entry wiring** (`src/App.tsx`): the Electron composition root creates one store, refreshes capability at boot, and mounts `library` / `library-category` routes (new for desktop) plus a Library header destination (`AppHeader`). TitlePage renders the real toggles when the library is available, keeping the previous disabled-with-reason buttons otherwise. The canonical id comes from the route's explicit media namespace (M3.1.1 rule): `tmdb:movie:N`, `tmdb:tv:N`, `tmdb:{mediaKind}:N` for TMDb anime, `anilist:N` for AniList anime — never `tmdb:N`, never stripped.
- **Library pages** (`src/pages/LibraryPage.tsx`): server mode shows underlined collection tabs, Movies/Series/Anime shelves with **full-scope counts** (independent of preview length), zero-count shelves present, unavailable-metadata entries rendered from the stored snapshot with an "Info unavailable" badge, sort selector (Recently added / Title A–Z via the shared SelectionSurface, route-persisted), loading/empty/error+Retry states, and the explicit "Library is not available on this server" state for missing capability. The scoped grid (`LibraryCategoryPage`) has collection+kind scope, both sorts, cursor pagination ("Load more", deduplicated canonical ids, truthful reload-from-page-one after a rejected cursor), and bounded "N of M titles" disclosure.
- **Boundaries honored**: browser fixture entry may inject a deterministic `LibraryController` fixture (explicit `?fixtures=1&library=<scenario>`, dev-only) for captures/tests; the production browser entry passes `libraryController: null` (M3.4 pending). No polling anywhere.

## 5. Accessibility / interaction checks

- Keyboard: toggles, tabs (roving tabindex via shared UnderlineTabs), sort button, Load more, Retry are real `<button>`s with shared focus-visible rings; the toggle is reachable and operable by keyboard (button semantics, not glyph-only handlers).
- Screen readers: every icon control has a specific accessible name ("Save to Watch Later"/"Remove from Watch Later"/"…— activate to retry"); pending/success/failure are announced via a polite live region (asserted in component tests); state is never color-only (fill + ring + text).
- 48×48 touch targets from the shared token; icon targets verified in captures.
- Direct/reloaded routes: Library routes are hash routes with collection/kind/sort params; a reloaded `#library?collection=favourites` restores tab and sort (route-persisted state), refetching from the server (fixture captures render these exact URLs).
