| Probe | Finding |

Client-side trace (executable, PASS): `electron-app/scripts/characterization/catalog-gateway.test.mjs` — "M3.1 identity trace":
- Cards keep ids opaque: numeric display id + `sourceKind` + `catalogId` + `providerIds` ride along; the client never parses or re-derives ids, so a server-side id change is client-invisible through `catalogId`.
- **Progress vocabulary is already media-qualified** (`tmdb:movie:N` / `tmdb:tv:N` / `anilist:N` / `mal:N` — `continue-service.parseSeriesId`), so watch progress needs **no rekeying**.

- **Documented gap**: TitlePage's bff loader builds `tmdb:<numeric>` for detail requests — the ambiguous form.

Traced surfaces (findings, no code change): catalog merge (safe, typed), detail lookup (ambiguous, proven), episodes (namespace follows title id), client caches (opaque ids — safe), routes (`kind` + numeric id — ambiguity surfaces at detail), resume/progress references (already qualified — safe).

## 2. Resolution — media-qualified identity, compatibly

- **Canonical ids become `tmdb:movie:N` / `tmdb:tv:N`** — deliberately matching the vocabulary watch progress ALREADY uses (`tmdb:movie:N` / `tmdb:tv:N` seriesIds), so no progress rekey and no new namespace invention.
- **Legacy `tmdb:N` = read alias** resolved by the documented movie→tv probe (current behavior, unchanged for old clients). Not stored, not guessed for writes.
- **Producers to change (M3.1.1)**: TMDb provider emits qualified ids (`tmdb.go` titleFromMedia/Detail/Episodes); Detail accepts the qualifier and probes ONLY that endpoint (no behavior change for unqualified input); Episodes' id map parsing handles the qualified form.
- **Consumers to change (M3.1.1)**: TitlePage bff loader requests detail by the card's opaque `catalogId`; `catalogIdForSeriesId` preserves the qualifier; merge keys unaffected (typed already). Continue-service enrichment uses qualified mapping.
- **Never**: guess an ambiguous mapping, silently rekey watch progress, or drop the legacy alias before consumers are verified.
- **Affected producers/consumers inventory**: producers = TMDb provider ids, episode ids; consumers = TitlePage (bff loader + legacy), PlayerPage (bff metadata via `tmdb:` ids), continue-service (`catalogIdForSeriesId`), catalog-bff (`backendTitleToCard` — opaque, no change), reference-client (catalog ids opaque), tests (parity fixtures use unqualified ids — alias keeps them green).
