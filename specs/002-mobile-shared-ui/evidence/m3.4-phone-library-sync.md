# M3.4 evidence — phone/browser Library integration + cross-client synchronization

Executed: 2026-09-10 (branch `001-build-torwatch-version` @ `5e9c648` + preserved M3.1.1–M3.3 diffs). Scope: M3.4 ONLY — enable the real server-backed Library controller in the production phone/browser entry and add bounded synchronization. **No native iPhone/Android packaging, no playback claims.**

## 1. Implemented behavior

- The production browser/phone entry (`src/browser/main.tsx`) now composes the SAME `LibraryStore` as desktop — one shared screen tree (`LibraryPage`, `LibraryCategoryPage`, `LibraryToggle`, TitlePage toggles), no duplicate mobile implementation, no Electron globals imported. Availability is gated on `library.household.v1`; older/incompatible/unreachable servers render the explicit unavailable/unreachable states (fixture mode unchanged, dev-only).
- **Sync controller** (`src/lib/library-sync.ts`, shared by BOTH entries — desktop attaches it too):
  - polls at most every **15s** (`POLL_INTERVAL_MS`), only while `document.visibilityState === 'visible'` and only while availability is `available` — an older server is never re-probed on a timer (proven by a zero-probe test);
  - refocus/visibility-resume/network-reconnect trigger a bounded refresh (5s minimum gap); reconnect also re-checks the capability once (event-driven, not polled);
  - `refreshAll()` reconciles BOTH collections' overviews plus every loaded page; a single refresh runs at a time (overlap guard in the store), so polls never stack; old-origin requests are aborted and discarded by the existing generation guards;
  - no polling while hidden (asserted: zero requests during hidden ticks).
- **Offline reads**: on a failed refresh, the previously loaded server snapshot stays on screen with `stale: true` and the pages render "Offline — showing the last synced data". This is the server's last delivered response — never a localStorage/device fork.
- **Offline writes**: never queued — a failed write surfaces the truthful error + Retry and nothing replays automatically after reconnect (asserted: PUT count unchanged after reconnect).
- **Cross-client synchronization**: `refreshAll` always reconciles BOTH collections' overviews, so changes to either flag (including from another client) become visible through the bounded poll. A full-scope zero count proves absence and reconciles stale confirmed flags (how a removal by another client becomes visible). Documented limitation: a removal inside a NON-empty collection cannot be proven from bounded reads, so a title-page toggle may retain the older flag until a write response or an empty-collection snapshot proves absence — the Library lists themselves always render server truth.
- Revisions remain lossless decimal strings compared per title/resource (BigInt) — untouched by M3.4.
