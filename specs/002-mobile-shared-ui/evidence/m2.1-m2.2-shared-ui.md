## CORS correction done FIRST (prerequisite from the assignment)

- Replaced wildcard CORS on the versioned surfaces (`/v1/version`, `/readyz`, `/v2/catalog/*`) with an explicit configurable origin allowlist: `TORWATCH_ALLOWED_CLIENT_ORIGINS` (CSV; default `null,http://localhost:5173` preserving the Electron `file://` renderer and dev server; a `*` entry is dropped with a boot warning).
- `internal/httpapi/cors.go`: `OriginAllowlist` + `allowlistCORS`. Requests WITHOUT an Origin header are served without CORS headers (unchanged behavior for curl/Electron main/non-browser tools); allowed origins get their origin echoed + `Vary: Origin`; disallowed origins get no CORS headers (browsers block; server response unchanged otherwise). Preflight answers OPTIONS with allow-methods/headers including the negotiation headers.
- Tests: `TestSystemAndCatalogEndpointsUseOriginAllowlistCORS` (allowed/disallowed/no-Origin GET; preflight methods/headers; no `*` assertions retained), `TestOriginAllowlistNeverAcceptsWildcard`, `TestAllowedClientOriginsDefaultParsesAndRejectsWildcard`. Live check: backend returned `acao=http://127.0.0.1:4173` (echoed origin) for the capture session via env config. The legacy `/watch/*` wrappers and all other endpoints were NOT touched. Deploy docs updated (`deploy/torwatch-server/.env.example`).
