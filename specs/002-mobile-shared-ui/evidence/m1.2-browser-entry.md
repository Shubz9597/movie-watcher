# M1.2 evidence — platform adapters and browser-safe entry

Executed: 2026-09-06. Implements feature 002 M1.2 per tasks.md, architecture.md adapter contract responsibilities, and change-map.md M1.2 row.

## Why isolated adapter work proceeds while interactive verification is pending

M1.2's scope is composition and behavior preservation: inject connection/origin/storage/platform ports, add a browser-safe entry, and keep Electron byte-compatible. None of that depends on an iPhone, a Radxa, or an interactive desktop session. The hardware-dependent gates (M0.2's interactive desktop smoke, M1.3/M1.4 real-device playback, M5/M6) remain open and unticked; this task's evidence is browser-renderable and automated, which is exactly what tasks.md allows to proceed ("M1.3/M1.4 can remain hardware-blocked while M2–M4 progress after M1.2").

## Implementation (all new code isolated; Electron entry untouched)

- `src/platform/contracts.ts` — interface-only ports: `ConnectionConfig`, `DeviceStorage`, `DesktopChrome`, `Platform` (kind `electron|browser|fixture`).
- `src/platform/electron.ts` — the ONLY module reaching `window.electronAPI` in the shared slice; call-time, guarded, no fabrication. Desktop chrome optional.
- `src/platform/browser.ts` — browser connection (URL `?server=` > localStorage `mw_server_origin` > build default) and storage adapters.
- `src/platform/fixtures.ts` — TEST-ONLY fixture adapter: explicit `fixtures=<scenario>` URL activation in the dev browser entry only; scenario fetch shim scoped to backend URLs; production entries never import it.
- `src/platform/PlatformProvider.tsx` — composition context; missing provider is a hard composition error (no silent fallback).
- `src/browser/main.tsx` + `src/browser.html` — browser composition root rendering the SAME shared `AppHeader`, `HomePage`, `TitlePage`, `SeeAllPage` (lazy via existing `route-loaders`); connection gate with checking/unreachable/incompatible states and an origin field; unknown-route fallback; no `WindowChrome`/`RuntimeStatusBar`/`TmdbConnectionGate` (desktop-only chrome/credentials).
- `src/lib/connection-service.ts` (new) — single runtime origin owner: `setBackendOrigin` bumps a generation, aborts tracked in-flight backend requests, resets the version-check cache, and notifies subscribers; `api-client.ts` now reads the live origin (default byte-identical: `http://localhost:4001`).
- `src/lib/services/catalog-bff.ts` — every backend request is abort-tracked and stale-guarded: a response that raced an origin switch throws `CatalogBffError('origin_changed')` instead of applying old-origin state.
- `vite.config.browser.mts` + `build:browser` — SEPARATE output (`dist-browser/`), so a mobile build can never wipe Electron's `dist/` (verified: dist still has all four entries).

## Server-side prerequisite discovered and fixed

`/v1/version`, `/readyz`, and `/v2/catalog/*` had no CORS headers, so ANY browser origin was refused before the app could even negotiate (the honest `unreachable` gate caught it). Read-only discovery/catalog surfaces now carry CORS + OPTIONS preflight (`internal/middleware.EnableCORS` + `corsHandler` in `system_handlers.go` / `catalog_handlers.go`, negotiation headers added to Allow-Headers). Contract test added: `TestSystemAndCatalogEndpointsCarryCORSForBrowserClients`. No credential-bearing surface is exposed; wildcard CORS on read-only contract endpoints matches the mobile milestone's cross-origin reality.

3. Fixture shim ignored the contracted `type` search filter (anime group showed every row). Fixed; characterized.
4. Missing CORS on discovery/catalog endpoints (server fix above).
