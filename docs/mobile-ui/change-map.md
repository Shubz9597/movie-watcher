## Required scripts and test entry points to add during implementation

Preserve `electron-app`'s existing `npm test`, `npm run build:renderer`, `smoke:ui`, `smoke:embedded`, and platform packaging entry points. Add clearly named scripts for shared UI fixtures/capture, mobile web build, and native builds only when implemented. Document exact commands and working directories in the evidence report. Do not label a browser `build:renderer` result as an iOS build.

Backend verification runs from `torrent-streamer`: `go test ./...` and `go vet ./...`. Renderer verification runs from `electron-app`: `npm test` and `npm run build:renderer`. Native checks use the chosen toolchain and host; version requirements are pinned after M1, not guessed from this document. Broad affected suites run at phase exits; targeted checks accompany individual changes.

## Work that can proceed while hardware is unavailable

Baseline inspection/tests, adapter extraction, fixture-backed shared UI, library API/database/client, recommendations and browser performance work are independent of Radxa setup. Preserve any desktop smoke failure as evidence. Actual iPhone playback, native lifecycle and final ARM64 throughput/recovery remain blocked until the required host/device is available. The agent continues independent tasks and lists the exact remaining gate.

## Alpha visual refinement boundary

The current wireframes are accepted for alpha, not final design quality. The agent should fix real alignment, spacing, clipping, focus, responsiveness, animation and usability defects discovered in the built app. It should not start another design-direction workshop or regenerate the wireframes instead of shipping the alpha. Record remaining visual refinements in `specs/002-mobile-shared-ui/evidence/visual-followups.md` with screenshots and concrete findings; creating that report does not exempt alpha usability/accessibility failures.
