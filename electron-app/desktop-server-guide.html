Set up TorWatch on Windows

TorWatch on Windows plays video on this computer. A TorWatch server does the rest: it finds and streams the torrents and keeps your library and watch progress. You can connect to a server you already run, or set up a new one on this computer.

Connect to an existing server

Use this when a TorWatch server already runs on another computer, for example a home server or NAS.

  1. Make sure this computer can reach the server: the same home network, or the same VPN (such as Tailscale) if the server is only reachable that way.
  2. In TorWatch, choose Connect to an existing server.
  3. Enter the server's address with its port, for example http://192.168.1.20:8080: the same address your other devices use. Enter only the address, without a page path.
  4. Select Test connection, then Save and start TorWatch. TorWatch restarts with the saved address.

Docker and provider keys (such as TMDb) belong on the server; this computer needs neither. Closing TorWatch leaves the server running.

Sharing watch progress between devices

Devices using the same server share its library. Watch progress (Continue Watching and resume points) is kept per viewing profile, and each device starts with its own. To continue another device's list on this computer, open Share watch progress with another device in TorWatch setup and enter that device's viewing profile ID before saving. Leave it empty to give this computer its own progress.

The person who runs the server can find the profile IDs in the server's watch_progress table (subject_id, with recent activity). Link to an existing ID; never change it on the other device.

Set up a new server on this computer

Use this to run your own server here, for example on a computer without access to another TorWatch server. It needs Docker Desktop with Linux containers.

Extract TorWatch Windows 2.0.1.zip, open PowerShell in its LocalServer folder, and run:

powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-TorWatchServer.ps1

The starter asks for your own provider keys (a TMDb API key; OpenSubtitles is optional), creates a database password and builds the included server. It starts the database, the TorWatch backend, Prowlarr, FlareSolverr and the gateway. Wait for Server ready: http://127.0.0.1:8080, then choose Set up a new server on this computer in TorWatch, enter that address, test and save.

This server keeps its own library and watch progress. The private settings the starter creates stay in your local application data folder; never share them. See LocalServer/README.md for status and stop commands and custom ports.

Advanced: run from a source checkout

This option requires Docker Desktop with Linux containers, and a checkout of the TorWatch source code. Start Docker Desktop before running these PowerShell commands.

From the repository root, build the server image and create your own environment file:

docker build -f deploy/torwatch-server/Dockerfile -t torwatch-server:desktop-v2 --build-arg TORWATCH_VERSION=2.0.0 torrent-streamer
Copy-Item deploy/torwatch-server/.env.example deploy/torwatch-server/.env
notepad deploy/torwatch-server/.env

In that file set these values. Choose a strong PostgreSQL password and provide your TMDb API key:

TORWATCH_DATA_DIR=C:/TorWatchServer
TORWATCH_IMAGE=torwatch-server:desktop-v2
TORWATCH_VERSION=2.0.0
POSTGRES_PASSWORD=your-own-strong-password
TMDB_API_KEY=your-own-tmdb-api-key
GATEWAY_PORT=8080

Keep the remaining defaults for a first installation. The data folder must have room for your downloads. Then start the stack:

docker compose --env-file deploy/torwatch-server/.env -f deploy/torwatch-server/compose.yaml up -d
curl.exe --fail http://127.0.0.1:8080/readyz
curl.exe --fail http://127.0.0.1:8080/v1/version

Once the readiness check succeeds, choose Set up a new server on this computer in TorWatch and enter http://127.0.0.1:8080. Test, then save. The desktop does not manage the Docker stack.

To inspect or stop your local stack:

docker compose --env-file deploy/torwatch-server/.env -f deploy/torwatch-server/compose.yaml ps
docker compose --env-file deploy/torwatch-server/.env -f deploy/torwatch-server/compose.yaml logs --tail 100 vod
docker compose --env-file deploy/torwatch-server/.env -f deploy/torwatch-server/compose.yaml stop

If connection fails

  • Server not ready: check the server database and container logs.
  • Server unreachable: check its address and port, and that this computer is on the server's network (or VPN).
  • Incompatible protocol: update the client or server to compatible versions.
  • Connection test passes but the catalog fails: check the server's TMDb credential and CORS allowlist. A packaged desktop uses Origin: null; if your server has an explicit TORWATCH_ALLOWED_CLIENT_ORIGINS, add null alongside its existing allowed origins and recreate the server container.

Keep server access within your trusted network or Tailscale. The current server package is designed for a trusted household.

Built-in services from an earlier version

Computers set up with an earlier TorWatch version can keep its built-in services. On the server screen, choose Keep using the built-in services set up earlier on this computer; TorWatch then starts them on every launch, as before. Saving a server address later switches this computer to that server.
