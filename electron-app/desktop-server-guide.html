Connect TorWatch on Windows

The desktop app connects to the Version 2 server you choose. MPV plays video on Windows; the server owns catalog data, sources, library and watch progress.

Use your homeserver

  1. Connect this PC to the same network or Tailscale network as your phone.
  2. In TorWatch, choose Homeserver.
  3. Enter the same server gateway URL used by your phone, including the port if needed. Enter the base address, without a page path.
  4. Select Test connection, then Save and open TorWatch. The desktop restarts with the saved address.

Docker and provider credentials belong on the server. They are not required on the Windows client. Closing TorWatch leaves your homeserver running.

Continue Watching from your phone

The household library is shared by the server. The current progress API also uses a viewing profile ID. To link the phone's existing Continue Watching records, expand Link Continue Watching from your phone in desktop setup and enter the phone's profile ID before saving. Leaving it blank keeps this desktop's separate progress profile on the same server.

For an inspectable iPhone development build, open TorWatch on the phone, enable Web Inspector in the phone's Safari settings, connect it to the development Mac, and select the app under Safari's Develop menu. In the Console, read (do not change) its stored ID:

localStorage.getItem('mw_device_id')

The HTTPS server URL itself does not expose this value. A server administrator can alternatively read the existing subject_id values and recent activity from watch_progress. Do not change the phone's ID: link the desktop to the existing one to preserve the phone history. Desktop playback retains its own writer/session identity and ordered checkpoints.

Host a server on this Windows PC

For a shareable installation, extract TorWatch Windows 2.0.1.zip, open PowerShell in its LocalServer folder, and run:

powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-TorWatchServer.ps1

The starter asks for your own provider keys, generates a database password and builds the included server source. It starts PostgreSQL, the backend, Prowlarr, FlareSolverr and the gateway. The image contains FFmpeg and FFprobe. An existing Gluetun container is left alone. This local server has its own database; use Homeserver for continuity with your phone.

Keep the ZIP for sharing. The private configuration the starter creates under your local application data folder must stay on your computer. See LocalServer/README.md for status/stop commands and custom ports.

Advanced: run from a source checkout

This option requires Docker Desktop with Linux containers, and a checkout of the TorWatch source code. Start Docker Desktop before running these PowerShell commands.

From the repository root, build the server image and create your own environment file:

docker build -f deploy/torwatch-server/Dockerfile -t torwatch-server:desktop-v2 --build-arg TORWATCH_VERSION=2.0.0 torrent-streamer
Copy-Item deploy/torwatch-server/.env.example deploy/torwatch-server/.env
notepad deploy/torwatch-server/.env

In that file set these values. Choose a strong PostgreSQL password and provide your TMDb API key:

TORWATCH_DATA_DIR=C:/TorWatchServer
TORWATCH_IMAGE=torwatch-server:desktop-v2
TORWATCH_VERSION=2.0.0
POSTGRES_PASSWORD=your-own-strong-password
TMDB_API_KEY=your-own-tmdb-api-key
GATEWAY_PORT=8080

Keep the remaining defaults for a first installation. The data folder must have room for your downloads. Then start the stack:

docker compose --env-file deploy/torwatch-server/.env -f deploy/torwatch-server/compose.yaml up -d
curl.exe --fail http://127.0.0.1:8080/readyz
curl.exe --fail http://127.0.0.1:8080/v1/version

Once the readiness check succeeds, choose Server on this PC in TorWatch and enter http://127.0.0.1:8080. Test, then save. The desktop does not manage the Docker stack.

To inspect or stop your local stack:

docker compose --env-file deploy/torwatch-server/.env -f deploy/torwatch-server/compose.yaml ps
docker compose --env-file deploy/torwatch-server/.env -f deploy/torwatch-server/compose.yaml logs --tail 100 vod
docker compose --env-file deploy/torwatch-server/.env -f deploy/torwatch-server/compose.yaml stop

If connection fails

  • Server not ready: check the server database and container logs.
  • Server unreachable: check its address, port and network/Tailscale access.
  • Incompatible protocol: update the client or server to compatible versions.
  • Connection test passes but the catalog fails: check the server's TMDb credential and CORS allowlist. A packaged desktop uses Origin: null; if your server has an explicit TORWATCH_ALLOWED_CLIENT_ORIGINS, add null alongside its existing phone origins and recreate the server container.

Keep server access within your trusted network or Tailscale. The current server package is designed for a trusted household.

Existing built-in local setup

Existing installations can keep their original managed local services. In connection settings, use Manage existing built-in local services. Selecting a Version 2 server saves the new connection and switches this desktop to the external-server flow.
